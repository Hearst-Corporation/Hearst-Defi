06 What's exposable who sees what, and what never leaves the backend

Expose to B2B client

  • Vault status, totalAssets, minimumDepositAtomic
  • Product term, factsheet allocation targets
  • chainId / fork label, on every event
  • Indexed proof events — full field set
  • On-chain allocation + drift
  • Profile identity, eligibility state
  • Honest empty / unavailable states

Admin only

  • Raw DB counts, indexer cursor state
  • /ready latency, DB reachability
  • Backend runtime: commitSha, providerMode, uptime
  • Chain RPC health, codePresent
  • Full MiningMetric telemetry (pre-revalidation)
  • Data hygiene classifications
  • Dev-bypass / review account existence

Never expose

  • SESSION_SIGNING_KEY, DATABASE_URL, KEEPER_PRIVATE_KEY
  • Raw admin-bypass mechanics
  • Full internal emails beyond legitimate admin need
  • Non-validated projections presented as facts
  • Seed/demo rows presented as real activity

Not available yet

  • Monthly BTC accumulation ledger
  • Any mainnet event — today, fork only
  • Audited maturity delivery actuals
  • Production custody attestation
  • Full BTC reserve trajectory curve
