01 Executive overview

Hearst Connect is a single-vault institutional DeFi platform — the Hearst Yield Vault: mining-backed structured yield, monthly USDC distributions, target APY range 8–15%, Cayman SPV, $250k min ticket, 60-day soft lock-up. Multi-vault is a first-class key (Yield / Defensive / BTC Plus, ADR-006). The product is built out, not a skeleton.

Six invariants that define the platform

#InvariantWhere
1APY is always a range, never a single pointsrc/lib/agents/apy-range.ts
2Every metric carries a provenance badge (Live/Oracle/Attested/Estimated/Manual/Stale)src/lib/data/*, freshness.ts
3Engine is pure — no DB, no fetch, no Math.random()/Date.now()src/lib/engine/* (verified)
4Navigation is 100% deterministic (regex before any LLM); model has no navigate toolsrc/lib/agentic/intent-router.ts

6Forbidden words guarded output-side, token-by-token (EN+FR)src/lib/llm/output-guard.ts

Ready vs to-harden, in one line. DS consolidated and locked · engine pure and tested · agentic safety deterministic and gated. The hardening frontier is deployment/DB integrity (no CI gate on prod deploy, prisma db push instead of versioned migrations) plus a few medium items (CSP unsafe-eval, rate-limit fallback).

09 Runtime flows

Investment (LP)

apply → onboarding (accreditation → Sumsub KYC → wallet) → browse vault → invest flow (subscribe.ts, TOCTOU-safe $transaction, idempotent on txHashOpen) → Position → portfolio view-state → monthly USDC distribution (distribution-executed event) → proof center.

Product construction (admin)

prompt in Product Workspace → live sources (Telegram ASIC + BTC + hashprice + DeFi yields) → pure engine (scenario/projection) → construction brief → create_vault_draft (DRAFT + token) → Vault Wizard lifecycle → governance/multisig gate → deploy (Base Sepolia; mainnet audit-gated).

Hourly / daily data pulse

market-data-hourly (0 * * * *) → MiningMetric DB → dashboard; custody/NAV snapshots (:05/:10); mining-health-daily, risk-daily → rebalancing-signal (event chain); investor-memo-monthly → PDF to Supabase Storage.

Chat turn

kill-switch → danger router → deterministic intent router → (nav OOB | product ack | outreach canvas | LLM read-only turn) → output guard → persist only if compliant.

10 Gaps and decisions

Ready areas

  • Engine — pure, deterministic, ~2400 vitest, seeded PRNG. Trustworthy compute core.
  • Agentic safety — deterministic router, danger-first refusal, draft-only + token writes, output guard EN+FR. No autonomous financial action path.
  • Design system — consolidated, one green, 3 surfaces, Catalyst-canon locked by tests.
  • Data provenance — every source server-only, never-throw, badged, conservative fallback.
  • Webhooks / auth — every webhook signature-verified fail-closed; sessions DB-backed, gates doubled.
