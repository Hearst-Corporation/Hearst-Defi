# Mining Model

## Core formulas

```
mining_revenue       = deployed_hashrate (TH/s) × hashprice ($/TH/day) × uptime (%)
operating_costs      = energy_cost + hosting_cost + pool_fee + maintenance
mining_gross_margin  = mining_revenue − operating_costs
```

Hearst does NOT operate ASICs directly. The note buys **exposure to the cashflow** via
revenue-share with 1–2 partner farms (ADR-003). Under **PermissionedDynaVault v2.1** the net
mining margin does **not** become a monthly USDC payout to LPs: it feeds the note's **BTC
accumulation** (pockets B1/B2), while the mining pocket's electricity is settled on-chain
through the **electricity account** (`payElectricity()` / `elecStatus()` / `monthlyElecCost()`).
On-chain mining is reported via `miningMetrics()` → (`hashrateTh`, `totalBtcEarnedSats`),
`Attested` provenance.

## Variables (Phase 1 — paper, Phase 2+ — partner-attested)

| Variable | Source | Frequency |
|---|---|---|
| deployed_hashrate | internal contracted / on-chain `miningMetrics().hashrateTh` | monthly |
| hashprice | Luxor / Hashrate Index API | daily |
| BTC price | Chainlink + Coingecko fallback | 1min |
| network difficulty | mempool.space | per adjustment |
| uptime | partner reporting | daily |
| energy_cost | contractual + spot index; settled via `payElectricity()` | monthly |
| pool fee | pool config | static |
| revenue_share_hearst | contract | static |

## The 3 Mining Health scores (visible on Dashboard)

### Mining Margin Score (0–100)
```
score = 50 + 50 × (current_margin / target_margin − 1)
clipped to [0, 100]
```
Thresholds: 🟢 ≥70 / 🟠 50–69 / 🔴 <50

### Hashprice Trend
```
trend_pct = (hashprice_30d_avg / hashprice_60d_avg − 1) × 100
```
Thresholds: 🟢 ≥−5% / 🟠 −5 to −15% / 🔴 <−15%

### Operational Confidence (0–100)
```
score = 50% × (uptime_30d / 95%, capped 100)
      + 30% × attestation_freshness_factor
      + 20% × energy_cost_stability
```

## Conditional logic into v2 mechanics

Allocation is fixed on-chain (40 / 27 / 33); the note responds through **curtailment**, the
**vending curve**, and **take-profit**, not sleeve reallocation:

| Condition | v2 response |
|---|---|
| BTC price below the configured pre/post-halving threshold | Mining pocket B1 is **curtailed** (`isCurtailed()` / `curtail()`; thresholds via `setCurtailmentThresholds` + `setHalvingMonth`) |
| BTC price above a configured tier | **Take-profit** executes on B2 (`setTakeProfitTier` / `executeTakeProfit` → `TakeProfitExecuted`) |
| Operating months elapse | B3 Reserve USDC depletes along the fixed **vending curve** (`vendingCurveBps(month)`, over `productDurationMonths()`) |
| Mining margin score < 50 sustained | Trigger human review (PTAI); no autonomous financial action |
| Halving approaching | Pre-position curtailment thresholds (`setHalvingMonth`) |

Curtailment thresholds, take-profit tiers, and the vending curve are **configured contract
parameters**, not promised performance figures.
