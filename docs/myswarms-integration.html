Architecture · Backend agentique

Hearst Connect × MySwarms

On arrête de gérer des agents à la main. Hearst Connect pilote le moteur d'orchestration crewai-engine de MySwarms par-dessus HTTP — kickoff → poll, token partagé — et délègue l'orchestration multi-agents (CrewAI) au lieu de la recoder à chaque fois.

Verdict efficacité : oui, ça marche mieux — pour tout ce qui a de l'orchestration réelle. On hérite des primitives (retries, boucles d'outils, mémoire, traces, HITL) au lieu de les construire ; un seul moteur, déjà rôdé sur plusieurs entités, un seul endroit à débugger. On garde les appels triviaux triviaux, et la garde de conformité reste côté Hearst Connect.

3 · Contrat d'intégration

AspectRéalité (recon)
Modèlekickoff → poll. POST /v1/swarms/{uuid}/kickoff?owner_id=… → 202 {run_id, swarm_id, status:"running"}, puis GET …/status/{run_id} jusqu'à completed / failed / cancelled.
AuthBearer token statique partagé — Authorization: Bearer <CREWAI_ENGINE_AUTH_TOKEN> (≥32 chars, identique des deux côtés). Comparaison constant-time. Pas de HMAC.
Multi-tenantowner_id (UUID) obligatoire sur quasi toutes les routes — sinon 400.
RobustesseRetry exponentiel [500, 1500, 4500]ms sur 502/503/504 (cold starts Railway). Rate limit moteur : 10 kickoffs/min → 429 + Retry-After.
HITLStatut paused_hitl + POST …/runs/{id}/resume avec {decision_id, value}.
AbsentPas de webhook push, pas de SSE, pas de HMAC entrant. Le « pattern Cortex HMAC » décrit ailleurs n'existe pas dans le repo — Cortex est consommé en sortie via simple x-api-key. Tout push/HMAC entrant serait à construire côté moteur.

// Dans un job Inngest / worker — JAMAIS dans un handler de requête (poll long).
import { runSwarmForText } from "@/lib/swarms/client";
import { SWARM_TEMPLATES } from "@/lib/swarms/config";

const { text } = await runSwarmForText(
  SWARM_TEMPLATES.HEDGE_CRYPTO_ANALYSIS,
  { trigger: "on_demand", inputs: { asset: "BTC", direction: "long" } },
  ownerId,                          // UUID tenant, obligatoire
);
// text est déjà passé par la garde conformité (forbidden words + APY range).

7 · Plan de migration

  1. Recon MySwarms — contrat réel relevé (endpoints, Bearer, templates, absence de HMAC/push).
  2. Couche de connexion + livrable HTML — src/lib/swarms/*, flag SWARMS_ENGINE (OFF), env optionnelles, ce document. Ne casse rien.
  3. Câbler les swarms dédiés — générer/persister les swarms via l'Architect, brancher les jobs Inngest dessus derrière le flag, garde sur chaque résultat.
  4. Bascule — router l'orchestration vers MySwarms, valider en parallèle de l'existant.
  5. Dégager A→Z l'ancien backend — retirer src/lib/agents/* + src/lib/llm/* et réparer les ~80 consommateurs une fois le chemin MySwarms vert (typecheck + tests). Le démontage est la dernière passe, pas la première.

Tout sur la branche feat/agent-canvas-workspace — prod intouchée tant qu'on ne merge pas sur main. Commit + push à chaque passe.
